# Safe routine provider evidence — November4 repair

This isolated source repair supersedes the November3 prose-filtering prototype, which remains preserved separately and uninstalled. Routine persistence and provider exception messages now use fixed metadata/classifications only. No arbitrary provider message/reason/detail/body value is copied into diagnostic evidence or support exports. Raw key/prompt/keywords are no longer supplied to evidence capture. Successful response bodies never enter this boundary.

Known code/type/param values use fixed vocabularies; unknown scalar values becomeOther with explicit UnrecognizedFields. Human-readable classification phrases are local constants derived from knowncodes, labelled FixedCodeClassification. They are not provider quotations or reconstructed explanations. OriginalExplanationOmitted/ProviderProseObserved and OriginalExplanationState distinguish observed-and-omitted prose, absence within allowlisted fields, and unavailable/uninspected bodies. Coverage is always AllowlistedFieldsOnly; limits never certify the entire payload. Status/UTC/duration/componentversion/endpoint role/operationclientID and hashedserverID remain. UI diagnostic parts also use safe fields and hashedserverID; raw properties retained in the transient typedexception are not dumped to logs or messages.

A private constructor and read-only collections prevent normal callers injecting forged evidence. JSON traversal is limited to128visited nodes,6traversal levels,16parser levels,8observed explanation fields and65536inputcharacters. Missing/empty/malformed-or-depth-limited/HTML/oversize/timeout/cancellation/transport/bodyread/UTF8 states are explicit; arbitrary nonJSON/HTML is never a fallback logstring. No regex/pattern detector is relied on to decide whether freeform prose is private. Counts and flags may disclose deliberate omission, not content. Existing no-auto-paid-retry/recovery/budget rules and nonthrowing logger behavior remain.

The existing2MiB/20ownedclosedfile rotation, bounded fallback/drophealth and create-new redacted support projection apply. Support export retains safe provenance/coverage/availability states but omits raw or classified prose again. No new ACL, storage context, credentials, browser extension or security settings are introduced.

The unrestricted FULL provider explanation requirement is still unmet: the safe routine repair intentionally omits arbitrary explanations rather than pretend patterns guarantee privacy. A separately designed, explicitly scoped private incident-capture/review workflow could address selected failures, with consent/data boundaries/expiry/export policy, and no blind paid replay. This repair adds no such live capture authority or raw-body store. Historical discarded explanations cannot be recreated. No deployment, installation or public ZIP change occurs in this task; synthetic tests and independent review are not live-provider acceptance.
