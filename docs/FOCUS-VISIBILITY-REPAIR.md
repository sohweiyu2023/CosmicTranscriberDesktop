# Bounded settings focus visibility repair (R2)

The settings keyboard-focus observer is attached at the window with handledEventsToo enabled. A focus transaction runs at most once for the inner SettingsViewport and once for outer WorkspaceViewport. A separate idle callback observes the first queued scroll/layout result before calculating the outer request. Focus changes, hidden/detached targets, window disposal and user wheel input cancel pending work. No key is handled or focus reassigned; no retry/reveal loop or periodic timer is used.

UI_VISIBILITY logs contain handler_enter/scheduled/before/requested/settled/complete/cancelled or fixed skip stages, source IDs and finite numeric rectangles/viewport sizes/offsets. They contain no control content or printable keys. Each reported fraction concerns that specific presenter; combine ancestor geometry and actual pixels before claiming overall visibility.
